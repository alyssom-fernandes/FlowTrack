# ADR 0006 — Demo Mode Runs Entirely in the Browser

**Date:** 2026-10-02  
**Status:** Accepted

## Context

The public demo used a real account (`demo@flowtrack.app`) on the production Supabase project, reset weekly by a scheduled GitHub Action. That kept the project awake, but GitHub disables scheduled workflows after 60 days without commits. The workflow stopped, the free Supabase project was paused for inactivity and later removed, and the public demo showed "Demo mode temporarily unavailable" to every visitor.

A portfolio demo cannot depend on a free-tier database staying awake.

## Decision

Demo mode runs entirely in the browser:

- `authService.signInDemo()` sets a session flag (`sessionStorage`) and emits a local session. No Supabase call is made.
- While the flag is on, the Axios instance uses a custom adapter (`src/demo/index.ts`) that routes every `/api/v1/*` request to an in-memory implementation of the API (`src/demo/backend.ts`). `services.ts` and the pages do not know the difference.
- The in-memory API mirrors the FastAPI rules: account balances adjusted on every write, goals computed from their period, budgets with spending, alerts, 30-day cash flow, net worth, 3-month projections, audit log with undo, OFX parsing. PDF import returns a sample statement.
- Seed data (`src/demo/seed.ts`) is generated relative to today: 12 months of history, with the current month compressed into the days already elapsed so the dashboard is never empty.
- State lives in `sessionStorage`: changes survive a reload and disappear when the tab closes. Nothing leaves the browser.
- Supabase became optional. Without `VITE_SUPABASE_URL`, the app runs in demo-only mode.

## Reasons

- **Always available**: the demo works with the backend asleep, deleted or never deployed.
- **No shared state**: visitors no longer overwrite each other's demo data, so the weekly reset is unnecessary.
- **Fast**: no network round trips; the demo feels like the real app on a fast connection.
- **Testable**: end-to-end tests and screenshots run against a local build with deterministic data.

## Consequences

- The business rules exist twice (Python and TypeScript). Changes to analytics must be made in both; the demo backend is kept small and commented to make that practical.
- Real PDF parsing (pdfplumber) only runs with the backend; the demo shows a recorded sample.
- AI categorization and insights in the demo are pre-computed from the seed data, not generated by Claude.
